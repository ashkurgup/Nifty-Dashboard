# Core Architectural Principles

## 1. Fault Isolation

Every new feature must fail independently.

No strategy/module should be capable of:

- crashing FastAPI
- blocking websocket loops
- corrupting Redis state
- freezing rendering
- interrupting market feed processing

---

## 2. Thin Core Principle

Core files must remain orchestration-only.

Target limits:

| File | Responsibility |
| --- | --- |
| `app.py` | Route registration + boot only |
| `ws_daemon.py` | Websocket lifecycle only |
| `system.py` | Shared utilities only |

Avoid business logic in core files.

Preferred pattern:

```
core/
modules/
services/
processors/
workers/
```

---

## 3. Frozen UI Structure

UI architecture must remain component-based.

Rules:

- One feature = one isolated HTML component
- Each component may contain:
    - internal CSS
    - internal JS
    - isolated rendering logic
- Avoid cross-component DOM dependencies
- Avoid global JS pollution
- Avoid shared mutable UI state

Goal:

```
Freeze completed UI modules permanently.
```

---

## 4. Redis Safety Protocol

All Redis access must be protected.

Required pattern:

```
@safe_redis
```

No direct Redis writes inside:

- websocket callbacks
- UI render loops
- strategy execution loops

Redis keys must follow namespace isolation:

```
live:
trade:
system:
strategy:
alerts:
```

---

## 5. Runtime Isolation

Long-running tasks must never block:

- websocket threads
- FastAPI request cycle
- Redis operations

Required safeguards:

- try/except isolation
- watchdog protection
- timeout handling
- retry throttling
- loop backoff protection

No uncontrolled:

```
whileTrue:
```

loops without sleep/backoff/error guards.
